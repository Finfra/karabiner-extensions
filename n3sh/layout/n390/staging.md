# 0. 개요

**배열: 390.** 본 배열 규칙표([rules.md](rules.md))에 넣기 전이거나 뺄 예정인 **작업 대기 항목**을 담는다. 배포 규칙이 아니므로 생성기(`gen_rules.py`)의 입력이 아니다.

* 데이터: [staging.json](../../core/n390/staging.json) — 총 38건 · 스키마: [staging_job.schema.json](../../core/schema/staging_job.schema.json)
* 쓰는 순서: **[1. Line](#1-staging-by-line) 에 한 줄로 던져 놓고**, 컬럼이 정해지면 [2. Table](#2-staging-by-table) 로 옮긴다. 둘은 같은 목적의 두 속도다

| job  | 뜻                                            | 목적지                                 |
| :--- | :-------------------------------------------- | :------------------------------------- |
| 추가 | 새로 넣을 후보                                | [rules.md](rules.md)                   |
| 수정 | 배포된 규칙의 출력·조건을 고칠 것             | [rules.md](rules.md)                   |
| 제거 | 뺄 예정                                       | [rules.md](rules.md) 에서 삭제         |
| 금지 | 비워 두기로 **결정**한 자리 — 배정 금지       | [rules_prohibit.md](rules_prohibit.md) |
| 미정 | 비어 있어 배정 가능하나 **아직 안 정한** 자리 | 없음 — 여기 머문다                     |

> **`금지` 는 표에 없다** — 2026-08-05 [rules_prohibit.md](rules_prohibit.md) 로 분리했다. staging 은 **전이 구역**이고 금지는 나가지 않는 영구 결정이라 성격이 다르다. `금지` 로 판단한 건은 위 [1. Line](#1-staging-by-line) 의 `금지` 줄에 적었다가 그 파일로 옮긴다.
>
> `미정` 은 목적지가 없어 머물지만 **SSOT 가 아니다** — 어떤 자리가 비었는지는 [rules.md](rules.md) 부재에서 유도되는 사실이고, 이 표는 그중 **손으로 골라 적어 둔 관심 목록**이다. 빠짐이 있을 수 있다(실제로 2026-08-05 전수 대조에서 13건이 뒤늦게 등재됐다).

> 셀 표기: `—` 는 빈 문자열, `␣` 는 공백 1칸이다. `c1`·`c2`(누르는 키)의 `␣` 는 **스페이스바 키**로 JSON 에 `_` 로 저장된다. 종성 자모는 `~` 접두([notation.md](../../_doc/notation.md)). 표를 고친 뒤 `python3 tools/md_to_json.py build` — 규약: `.claude/rules/data-md-first-rules.md`

* **`c1`+space 전수 대조**(2026-08-05): 초성 `'` 1 · 중성 `4 5 6 7 e b` 6 · 종성 `q w a s z x` 6 = **13건**을 미정으로 등재. 중성은 이중모음 축약(ㅘㅙㅚㅝㅞㅟㅢ)이 이미 `f r t c v g d` 를 다 채웠고, `9`·`/` 는 이중모음 **선행키**라 자모 단독 키가 아니어서 제외했다
* 미정 행의 `DESC` 앞 `난이도 N` 은 사용자 기입 타건 난이도다(구 `easy` 컬럼 — 2026-08-05 통일 표에 흡수)
