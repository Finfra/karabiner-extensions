# 0. 개요

**배열: 최종식.** 본 배열 규칙표([rules.md](rules.md))에 넣기 전이거나 뺄 예정인 **작업 대기 항목**을 담는다. 배포 규칙이 아니므로 생성기(`gen_rules.py`)의 입력이 아니다.

* 데이터: [staging.json](../../core/final/staging.json) — 총 20건 · 스키마: [staging_job.schema.json](../../core/schema/staging_job.schema.json)
* ⚠️ **최종식 판정은 미시작**이다 — 내용 대부분이 2026-08-02 배열 분리 시점의 사본이며 최종식 기준으로 재검토된 적이 없다
* 구조는 390 판과 동일하다. job 의 뜻·목적지·`미정` 이 SSOT 가 아닌 이유는 [n390/staging.md](../n390/staging.md) "0. 개요" 가 정본이며 여기 사본을 두지 않는다
* `금지` 는 이 표에 없다 — [rules_prohibit.md](rules_prohibit.md) 로 분리(2026-08-05)

**2026-08-05 정리 실측**: 구 76행 중 **실내용은 30행**이고 46행이 전 컬럼 빈값(Numbers 원본 자리표시)이었다. 390 이 2026-08-02 에 한 것과 같은 기준으로 빈 행을 제거했다. 내역 — 금지 4건은 [rules_prohibit.md](rules_prohibit.md) 로 · 미정 17 + 수정 2 + 추가 1 = 20건은 아래 표로 · 트리거 없이 메모만 있던 5건은 [1. Line](#1-staging-by-line) 으로 · 전 컬럼이 `3키` 인 잡행 1건은 폐기.

> 셀 표기: `—` 는 빈 문자열, `␣` 는 공백 1칸이다. `c1`·`c2`(누르는 키)의 `␣` 는 **스페이스바 키**로 JSON 에 `_` 로 저장된다. 종성 자모는 `~` 접두([notation.md](../../_doc/notation.md)). 표를 고친 뒤 `python3 tools/md_to_json.py build`

# 1. Staging by Line

컬럼을 채우기 전에 **빠르게 던져 놓는 자리**. 정리되면 아래 표로 옮긴다(`금지` 만 [rules_prohibit.md](rules_prohibit.md) 로).

* 추가 : `즉, ` (트리거 미정) · `기` — Ex) 찾기. (트리거 미정)
* 금지 : ㄱ* 사용 (대상 미상) · 가성비 안나옴 (대상 미상) · ㄹ* 사용 (대상 미상)
