**최종식 판 규칙 서술**이다. 공통 수집본([_doc/rules_notes_intersection.md](../rules_notes_intersection.md))에서 배열별로 분리했다(2026-08-04) — 390 판은 [n390/rules_notes.md](../n390/rules_notes.md).

정본 데이터는 [rules.md](../../layout/final/rules.md), 표기는 [notation.md](../notation.md).

> ⚠️ **최종식은 라이브에 배포돼 있지 않다.** 아래는 전부 `Extensions/n3sh/core/final/` 정본과 오라클에서 계산한 값이며, **실기 타건으로 확인된 것이 아니다**. 390 판(사용자가 매일 쓰는 배열)과 확실성 등급이 다르다.

# 출력 꼬리 — 공백·기호

## 규칙1. 조사·명사형 뒤에는 공백이 자동으로 붙는다

`sp=✔` 인 행은 출력 끝에 `spacebar` 가 붙는다.

| 품사 | sp=✔ | 비고 |
| :--- | :--- | :--- |
| `p` 조사 | 24 / 29 | 예외 5건은 수식키 변형(규칙2) |
| `n` 명사형 | 11 / 11 | 예외 없음 |
| `e` 어미 | 93 / 105 | 나머지는 ⌥ 변형 등 |

* 390 판과 같은 규칙이다(비율만 행 수 차이로 다름)

## 규칙2. `⌥` 변형은 꼬리가 없다

`⌥=✔` 인 행은 **`기호`·`sp` 컬럼과 무관하게** 자모만 출력한다.

* 검증: `⌥=✔` **16행 전량**이 꼬리 없음, 예외 0건(2026-08-04 계산)
* 390 판과 동일

## 규칙3. 기호 대응 — ⇧ 가 `?`, ⇧⌘ 가 `!` (**390 과 같다** — 2026-08-06 실기 확인)

| 수식키 | `기호` 컬럼 | 실제 키 | 출력 |
| :--- | :--- | :--- | :--- |
| 무수식 | `.` | `period` | `.` |
| `⇧` | `?` | `slash` | **`?`** |
| `⇧⌘` | `!` | `b` | **`!`** |
| `⌘` | 행마다 다름 | `period` / 없음 | — |

✅ **해소(2026-08-06)** — 오래 `🚧 미해소` 로 남아 있던 불일치다. 원문(Numbers, 최종식 시절)은
`⇧`=`!`·`⇧⌘`=`?` 라고 적는데 정본 데이터는 `⇧`=`?`·`⇧⌘`=`!` 였고, 어느 쪽이 맞는지 몰랐다.

**데이터가 옳다.** 사용자가 macOS 입력 소스를 세벌식 최종으로 두고 직접 입력해 확인했다 —
`⇧`+`/` → `?` · `⇧`+`b` → `!`.

* **판정에 배포가 필요 없었다는 것이 핵심이다.** 규칙이 내보내는 것은 키코드(`slash`·`b`)이고 양 배열이
  동일하므로, 질문은 *"n3sh 규칙이 무엇을 내는가"* 가 아니라 *"세벌식 최종 **입력기**가 그 키를 무슨
  문자로 내는가"* 였다. 입력 소스만 바꾸면 2키로 답이 나온다 — 미배포는 판정 불가의 사유가 아니었다
* 따라서 **기호 대응은 배열별로 갈리지 않는다**. 원문이 낡았거나 틀린 것이며, 최종식 `기호` 컬럼
  60행은 지금 값이 맞다(⇧ 31건 · ⇧⌘ 29건)

# 트리거

## 규칙4. 같은 트리거를 두 행이 쓸 수 없다

`(c1, c2, ⌥, ⇧, ⌘)` 복합키는 유일해야 한다. Karabiner 는 같은 `from` 중 먼저 나온 것만 발동시키므로 뒤엣것은 **죽은 규칙**이다.

* 집행: `tools/validate_schema.py` `check_trigger_unique`
* ✅ 해소(2026-08-05) — `함`(`m+l` 무수식)이 어미·명사형 두 행이었다. 390 과 같은 사안이라 같은 판정으로 `품사 n` 행을 삭제했다(출력이 `함.␣` 로 동일해 산출 불변). 현재 이 규칙의 미해소 건은 0 이다

## 규칙5. 실제로 쓰는 기호 키는 10종

```
'  ,  -  .  ;  [  \  ]  ␣  ⏎
```

* 390 판과 **완전히 동일**하다(2026-08-04 양 배열 전수 대조)
* 원문 규칙5는 8종만 적고 있다 — `-`·`\` 누락

## 규칙6. 조사는 패턴 규칙이라 `억지` 가 아니다

`억지=✔` 는 자모 조립이 불가능해 오라클 키열을 그대로 써야 하는 행에만 붙인다. 그 literal 은 [oracle_final.json](../../core/oracle_final.json) `manual_overrides` 로 지정한다.

* 최종식의 `manual_overrides` 는 에서 **최초 신설**됐다(`될` 재배치 1건)

# 390 과의 차이

두 배열이 갈라지는 지점만 적는다. 나머지 213행은 교집합이다([rules_Intersection.md](../../layout/rules_Intersection.md)).

| 출력 | 최종식 | 390 | 비고 |
| :--- | :--- | :--- | :--- |
| `ㅒ` | `g+f` | `r+f` | 트리거 자체가 다른 유일한 유형(pattern A) |
| `될` | `u+[` | `u+[` |·48 — 양 배열 모두 구 `u+]` 에서 이동 |
| `해` | `m+;`+⌘ **비활성** | 해당 행 없음(staging `지정안할` 이관) | ⌘+m 이 macOS 윈도우 최소화에 선점 |

* 출력만 다른 유형(pattern B·C, 9건)은 [keymap_final_to_390.json](../../core/keymap_final_to_390.json) 참조
* 최종식 정본은 **390 단계 설계 대상이 아니다** — 단계를 담는 `id` 컬럼이 전량 공란이다
