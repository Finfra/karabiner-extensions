# 여기 있는 것

**기각된 후보 6종**과 그 사인(死因)이다. 되살릴 일은 없다. 같은 자리를 다시 파지 않기 위해 남긴다.

> 이 폴더의 값어치는 JSON 이 아니라 **"왜 안 되는지"** 다. 새 트리거 키를 떠올렸을 때 여기부터 보면 이미 죽은 길인지 알 수 있다.

# 1차 (A·B·C) — 실기 전에 탈락 (2026-08-07)

라이브 설정을 안 보고 설계했다. 눌러 볼 것도 없이 트리거 키가 이미 임자가 있었다.

| 후보 | 트리거              | 사인                                                                                                 |
| :--- | :------------------ | :---------------------------------------------------------------------------------------------------- |
| A    | `⌘(오른쪽)` + 글자  | 오른쪽 ⌘ 를 이미 다른 용도로 쓰는 중(사용자). device 666 은 `right_command` → `keypad_comma`(한/영)  |
| B    | `⌘(오른쪽)⇧` + 글자 | 위와 같고, 게다가 **⇧ 를 트리거에 넣으면 대문자를 못 친다** — ⇧ 는 비워 둬야 한다                    |
| C    | `⌥(오른쪽)` 홀드    | 오른쪽 ⌥ 가 device 단에서 이미 리매핑돼 **complex 규칙에 `right_option` 으로 도달하지 않는다**       |

## C 의 사인이 교훈이다 — device 단 리매핑이 먼저 먹는다

라이브 `simple_modifications` 실측에서 오른쪽 ⌥ 의 행선지가 키보드마다 이미 정해져 있었다:

| device | `right_option` → |
| -----: | :---------------- |
|  24814 | `keypad_comma` (한/영) |
|  41208 | `keypad_comma` |
|  50484 | `keypad_comma` |
|   6400 | `right_command` |
|  49304 | `right_command` |
|   6481 | `right_command` |

**`simple_modifications` 가 `complex_modifications` 보다 먼저 적용된다.** 그래서 device 단에서 바뀐 키는 complex 규칙에 원래 이름으로 도달하지 않는다. 트리거 키를 고르기 **전에** 라이브 `simple_modifications` 를 읽는 것이 순서다.

# 2차 (D·E·F) — 사용자 판정으로 전량 기각 (2026-08-07)

1차 폐기 후 남은 물리 트리거(한/영 키 · `fn`)로 다시 짠 것들이다. **사용자가 전부 불가 판정**했다.

| 후보 | 트리거                     | 감수해야 했던 대가 (= 기각 사유로 추정)                                                                        |
| :--- | :------------------------- | :--------------------------------------------------------------------------------------------------------------- |
| D    | 한/영 키(`keypad_comma`) 홀드 | 한/영 이 key-down 이 아니라 **key-up 에** 나간다. 가장 많이 치는 키의 감각이 바뀐다 + 입력소스 전환이 글자당 왕복 |
| E    | 한/영 키 + 글자 모아치기      | 부작용은 0 이었으나 **한 번에 한 글자**. `API` 를 세 번 모아쳐야 한다                                            |
| F    | `fn` 홀드                  | 한글 모드인 동안 `fn`+F1~F12(밝기·볼륨) · `fn`+방향키 · `fn` 단독이 **전부 죽는다**. 외장 2종은 아예 무효        |

* ⚠️ 위 "기각 사유"는 **각 후보가 안고 있던 알려진 대가**이지, 항목별 타건 결과가 아니다. 사용자 판정은 *"지금까지 대안 모두 불가"* 였고 항목별 실측표는 채워지지 않았다
* E 는 2026-08-07 라이브에 잠시 배포됐다가 같은 날 제거됐다

## 살아남은 것 (G 로 계승)

* `input_source_if` 로 **한글일 때만** 거는 조건
* **`keyboardLayoutSettingIsEng` 를 레이어 변수로 재사용** — n3sh 254행이 전부 이 변수 0 을 조건으로 달고 있어, 1 로 올리면 n3sh 가 통째로 잠긴다(배선되지 않은 채 있던 off 스위치)
* **홀드 레이어** 기전 — 입력소스 전환이 시퀀스당 1회라 비동기 경합이 최소. C → F → G 로 이어졌다
* `from.modifiers.optional: ["any"]` 로 ⇧ 통과 → 대문자 자유
* 초안 결함 5건 교정형(`type: basic` · 소문자 `key_code` · `simultaneous` 제거 · rule 껍데기)
