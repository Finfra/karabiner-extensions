# 왜 `insert` 인가 — 남은 유일한 빈 키

앞선 6종이 죽은 이유는 하나로 요약된다. **이 프로필에서 모디파이어는 전부 임자가 있다.**

| 키                    | 상태                                                                            |
| :-------------------- | :------------------------------------------------------------------------------ |
| 오른쪽 ⌘              | 사용자가 다른 용도로 사용 중 · device 666 은 `keypad_comma` 로 리매핑           |
| 오른쪽 ⌥              | device 6종에서 `keypad_comma`·`right_command` 로 리매핑 — complex 에 도달 안 함 |
| 오른쪽 ⌃              | 다수 device 에서 `delete_forward`                                               |
| caps_lock             | Hyper(⇧⌘⌥⌃) / Escape                                                            |
| ⇧                     | **비워 둬야 한다** — 대문자를 쳐야 하므로 트리거에 못 넣는다                    |
| 한/영(`keypad_comma`) | 쓸 수는 있으나 D·E 로 시도해 기각                                               |
| `fn`                  | 쓸 수는 있으나 F 로 시도해 기각 (fn 기능 전부 희생)                             |

`insert` 는 다르다:

* **기존 규칙 점유 0건** — n3sh 254행 · FootPedal · 12Key2Knob · RemoteDesktop 전부 실측 `insert` 0
* **macOS 기본 기능 없음** — 잃을 것이 없다. F 가 `fn`+F키·방향키를 통째로 죽인 것과 정반대
* **device 단 리매핑 없음** — `insert` 를 `from` 으로 쓰는 simple_modification 이 없어 complex 규칙에 그대로 도달한다
* 한/영 키를 안 건드리므로 **가장 많이 치는 키의 감각이 그대로**다 (D 의 사인)

# G — Insert 홀드 레이어 ([G.insert-hold.json](G.insert-hold.json))

`insert` 를 **누르고 있는 동안 영문**, 떼면 한글. 누른 채 `a`, `l`, `a l` … 몇 글자든 연속으로 친다.

| 항목           | 값                                                               |
| :------------- | :--------------------------------------------------------------- |
| 입력소스 전환  | **시퀀스당 2회** (누를 때 en · 뗄 때 ko) — 글자 수와 무관        |
| 대문자         | `⇧` 통과 → `Insert`+`⇧a` = `A`                                   |
| n3sh           | 홀드 중 `keyboardLayoutSettingIsEng = 1` → **254행 통째로 잠김** |
| 기존 키 부작용 | **없음** (`insert` 는 어디에도 안 쓰인다)                        |
| manipulator    | 시험판 3건 (레이어 1 + `a`·`l` 2) → **정본 2건** (레이어만)      |

# 조합중 글자 — space+backspace 선행 (2026-08-07 실기 후 추가)

## 증상

한글은 **다음 글자의 초성이 들어와야** 앞 글자가 확정된다. `아` 를 치면 아직 조합중(preedit)이고, 이 상태에서 `Insert`+`a` 를 누르면 **`아` 가 지워지고 `a` 만 남았다**. 입력소스를 바꾸는 순간 IME 가 확정되지 않은 조합을 **커밋하지 않고 버리기** 때문이다.

## Karabiner 에는 조합 상태를 볼 수단이 없다 (확인함)

[공식 조건 문서](https://karabiner-elements.pqrs.org/docs/json/complex-modifications-manipulator-definition/conditions/) 기준 지원 조건은 7종뿐이다:

`frontmost_application` · `device` / `device_exists` · `keyboard_type` · `input_source` · `variable` · `expression` · `event_changed`

**IME 조합·preedit 상태를 노출하는 조건은 없다.** "조합중이면" 이라는 분기 자체가 불가능하므로, Keyboard Maestro 가 쓰던 것과 같은 **무조건 space+backspace** 가 유일한 길이다.

## 처리 방식 — 레이어 진입 시 1회

space 가 조합을 확정시키고(`아` 커밋 + 공백 1칸), backspace 가 그 공백을 지운다. 순수 효과는 **"조합중이면 확정, 아니면 아무 일 없음"**.

이 두 키를 **글자마다가 아니라 `Insert` 를 누르는 순간 한 번만** 보낸다 — 홀드 레이어라 진입이 시퀀스당 1회뿐이라서 가능한 배치다.

```json
"to": [
  {"key_code": "spacebar",           "hold_down_milliseconds": 10},
  {"key_code": "delete_or_backspace","hold_down_milliseconds": 10},
  {"key_code": "vk_none",            "hold_down_milliseconds": 30},
  {"set_variable": {"name": "keyboardLayoutSettingIsEng", "value": 1}},
  {"select_input_source": {"language": "^en$"}}
]
```

* **순서가 전부다** — space·backspace 는 **한글 IME 가 아직 살아 있을 때** 도착해야 한다. 그래서 `select_input_source` 보다 앞이다
* `vk_none` 30ms 는 **경합 방지 지연**이다. 키 이벤트는 앱·IME 에 비동기로 전달되는데 `select_input_source` 는 즉시 호출이라, 지연이 없으면 전환이 먼저 일어나 space 가 한글 IME 를 못 만날 수 있다
* 총 지연 ~50ms, `Insert` 를 누를 때 **한 번만** 발생한다

## ⇧ 가 space 에 얹히면 안 된다 (2026-08-07 2차 실기)

조합 확정은 통과했으나 **대문자에서 꼬였다.** `⇧`+`space` 가 이 환경의 **한/영 전환 단축키**라, 우리가 보낸 `spacebar` 에 눌린 ⇧ 가 얹혀 전환이 한 번 더 일어난 것이다.

원인은 레이어 키의 `from.modifiers` 가 `optional: ["any"]` 였던 것 — **optional 모디파이어는 출력에 그대로 통과한다.** 그래서 space 가 `⇧space` 로 나갔다.

고침은 레이어 키를 **2분기**로 쪼개 모디파이어를 **소비**시키는 것이다:

| #    | `from.modifiers`         | 역할                                                                     |
| :--- | :----------------------- | :----------------------------------------------------------------------- |
| 1    | `{"mandatory": ["any"]}` | 눌린 모디파이어를 **전부 소비** → 우리가 보내는 space 는 언제나 맨 space |
| 2    | (없음)                   | 모디파이어 없이 눌린 경우                                                |

* `mandatory` 로 잡힌 모디파이어는 **그 manipulator 의 출력에서만** 빠진다. 물리 ⇧ 는 계속 눌린 상태라 뒤따르는 `a` 는 정상적으로 `A` 가 된다(⌘h→← 를 걸어도 ⌘c 가 살아 있는 것과 같은 원리)
* ⇧ 만 막은 게 아니라 **`any`** 로 잡았다 — `⌘space`·`⌃space`·`⌥space` 도 전부 입력소스 전환 계열 단축키라 같은 사고가 난다. 하나씩 막는 대신 통째로 소비한다
* ⇧ 를 Insert **뒤에** 누르든 **먼저** 누르든 둘 다 덮인다 — 먼저면 1번, 뒤면 2번이 매치되고 어느 쪽도 space 에 ⇧ 가 안 붙는다

## 대가 (감수하는 것)

* 조합중이 아닐 때도 space+backspace 가 나간다. 순 효과는 0 이지만, **되돌리기(⌘Z) 이력에 남거나** 자동완성·자동수정이 붙은 편집기에서는 반응이 있을 수 있다
* 커서가 **줄 맨 앞**일 때 backspace 가 줄바꿈을 지울 여지 — space 를 먼저 넣으므로 그 space 를 지우는 것이 정상 경로지만, space 를 삼키는 앱(일부 터미널·vi 노멀 모드)에서는 앞 문자를 지울 수 있다. 판정 항목 10번에서 본다

## 26글자로 늘릴 때 manipulator 는 늘지 않는다

`insert` 를 누른 순간 이미 입력소스가 영문이라 **manipulator 가 없는 글자도 영문으로 나간다.** 여기 `a`·`l` 2건은 눌린 `insert` 가 출력에 새는 걸 막는 보험일 뿐이다.

실기에서 새지 **않으면** 그 2건을 지워도 되고, 그러면 G 는 **manipulator 1건짜리 규칙**으로 알파벳 26자 + 숫자 + 기호 전부를 덮는다. 판정 항목 7번이 이걸 본다.

## 알아 둘 것 — `insert` 가 물리적으로 어디 있나

이 프로필에서 `insert` 를 **내보내는** device 가 하나 있다:

| device | 매핑                                                                                                                  |
| -----: | :-------------------------------------------------------------------------------------------------------------------- |
|   3620 | `delete_or_backspace` → **`insert`** (같은 device 에서 `keypad_plus` → `delete_or_backspace` 로 백스페이스를 옮겨 둠) |

즉 그 키보드(숫자패드 계열)에서는 백스페이스 자리 키가 Insert 로 나간다. 풀사이즈 키보드라면 Insert 키가 그대로 있다.

**어느 물리 키가 `insert` 를 내는지 모르겠으면** Karabiner-EventViewer 를 열고 눌러 보면 된다 — 실제 도달하는 `key_code` 가 그대로 찍힌다:

```bash
open -a "Karabiner-EventViewer"
```
